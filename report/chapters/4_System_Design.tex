\section{System Architecture}
The system architecture of CodeInsight is designed as an end-to-end, sequential processing pipeline that transforms raw source code files into structured, actionable technical debt telemetry. Rather than relying on a heavy monolithic architecture or external database servers, the platform separates user interaction, API orchestration, AST parsing, and risk evaluation into distinct, well-coordinated stages. The pipeline executes through seven well-defined stages, ensuring deterministic data transformation at each phase:
\begin{enumerate}
    \item \textbf{User (Selects Source Code Repository):} The workflow begins with the user selecting or specifying the target source code repository on the local filesystem. The user provides the directory path to be evaluated through the web interface.
    \item \textbf{React Frontend (User Interface):} The React user interface captures the user's input, validates the path format on the client side, and initiates an asynchronous scan request by dispatching a REST call to the backend server.
    \item \textbf{Node.js + Express (Backend API):} The Node.js Express server acts as the API gateway and orchestration layer. It manages the asynchronous scan queue, validates directory existence and permissions on the host system, and spawns the native analysis engine process while tracking scan execution state.
    \item \textbf{C++ Code Analyzer:} The high-performance C++ engine performs recursive directory traversal with intelligent file filtering. It parses supported source files into concrete syntax trees using Tree-sitter grammars, computes exact McCabe cyclomatic complexity ($M = 1 + D$) and maximum control-flow nesting depth, and detects Type-1 code clones through a normalized sliding-window token hashing pipeline.
    \item \textbf{Risk Scoring Engine:} The risk scoring module processes the extracted metrics (complexity, duplication, and structural dimensions). It computes a normalized composite technical debt risk score ($R = 0.45C + 0.35D + 0.20S$) and assigns clear remediation priority tiers ($P1$--$P4$) along with human-readable risk factors.
    \item \textbf{JSON Results (Risk Score \& Severity):} The aggregated metrics, file-level diagnostics, clone clusters, and severity rankings are packaged into structured JSON payloads. This intermediate representation enables zero-dependency in-memory persistence and standardized export serialization.
    \item \textbf{React Dashboard (Tables, Charts \& Reports):} The frontend ingests the structured JSON telemetry, rendering an interactive developer dashboard complete with repository-level summary cards, debt distribution charts, searchable and sortable file tables, detailed function inspection modals, and export capabilities (JSON, CSV, Markdown).
\end{enumerate}

In Figure \ref{fig:dfd1}, the repository path passes to Process 1.0 (File Filtering \& Discovery), which ignores minified files, vendor dependencies, and binary assets. Valid source files flow into Process 2.0 (AST Parsing \& Complexity Extraction) to determine function-level decision points and nesting depths. Finally, Process 5.0 (Dashboard Telemetry) pulls the stored snapshots and renders real-time visual reports.

As illustrated in Figure \ref{fig:dfd2}, the technical debt evaluation pipeline decomposes into five distinct sub-processes:
\begin{itemize}
    \item \textbf{Sub-process 4.1 (Normalize Complexity):} Ingests raw function complexity metrics (McCabe cyclomatic complexity $M = 1 + D$) and scales them into a normalized complexity score $C \in [0, 100]$.
    \item \textbf{Sub-process 4.2 (Normalize Duplication):} Evaluates multi-file code clone percentages identified by the token hashing pipeline, producing a normalized duplication score $D \in [0, 100]$.
    \item \textbf{Sub-process 4.3 (Calculate Structural Score):} Aggregates physical line metrics, unusually long lines, and control-flow nesting depth to derive a composite structural health score $S \in [0, 100]$.
    \item \textbf{Sub-process 4.4 (Calculate Overall Risk):} Synthesizes the normalized scores ($C$, $D$, $S$) with calibrated weights (45\%, 35\%, and 20\% respectively) according to the formulation $R = 0.45C + 0.35D + 0.20S$, producing an overall risk score bound within $[0, 100]$.
    \item \textbf{Sub-process 4.5 (Assign Severity):} Evaluates the overall risk score against discrete heuristic thresholds, categorizing files into Low, Moderate, High, or Critical severity tiers and generating actionable, metric-based remediation explanations.
\end{itemize}
